# 专家视角文案方法论

把专业主题写成"普通大众能 get 到、又有专家判断力"的短视频脚本。

## 核心问题

复述定义和比喻，只会得到"太普通、没见解"的稿子。好的科普脚本需要一个**有反差、有态度、能让人"哦原来如此"的判断**，并且这个判断要能落成一句金句。

## 三步法

### 1. 找一个"竞争焦点转移"的洞察

别问"这个东西是什么"，问"大家一直以为拼的是 A，其实决定成败的是 B"。

- 普通讲法："DSH 是一个插件化框架。"
- 专家讲法："Agent 的未来，不只拼大脑多聪明，更拼工作台换错零件后能否收场。"

把焦点从"模型智商"转移到"运行底座的容错能力"——这就是洞察。

### 2. 用一句金句钉住它（20~35 字，口语，有反差）

金句标准：
- 能直接念出来（交给 TTS）
- 一听就记得住
- 不吹牛、和真实能力相符

放的位置：**开头钩子**（反转惯性认知）或 **结尾收口**（升华）。

### 3. 守住事实边界

金句可以犀利，但事实不能错。写之前先明确"不能说的"：
- 不把 developer preview 说成成熟平台
- 不把"推理时协作"说成"模型自学习/AGI"
- 不把"框架可撤销"说成"外部行为都能撤销"

## 写作约束

- 句子短，能直接交给 TTS 念
- 比喻用生活经验锚定（大厨/后厨、焊死的电路板、乐高拔插）
- 全文约 380~450 字，7 屏，65~75 秒
- 每屏一个中心，不堆概念

## 已沉淀的比喻库

| 概念 | 比喻 |
|---|---|
| 模型 vs Harness | 大厨 vs 后厨 |
| 传统 agent 难改 | 零件焊死在电路板上，换一个要重启 |
| 一切皆插件 | 乐高积木，能拔能插 |
| 拆得干净（时间可组合性） | 每装一个零件交一张"撤销回执"，拆时倒序还原 |
| 自动接线（空间可组合性） | 插件只声明需要谁，接口自动对准 |
